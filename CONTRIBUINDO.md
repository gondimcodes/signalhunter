# Contribuindo

## Boas-vindas

Agradecemos o interesse em contribuir com o SignalHunter!

## Antes de Abrir uma Issue

- Pesquise nas issues existentes para evitar duplicidade.
- Forneça informações suficientes sobre o problema ou contexto.
- Inclua logs sempre que possível.

## Relatando Bugs

Ao abrir um relatório de bug, inclua:
- Ambiente de execução
- Sistema Operacional e versão
- Versão do compilador Rust (`rustc --version`)
- Passos para reproduzir o problema
- Comportamento esperado
- Comportamento real / observado

## Sugestões de Novas Funcionalidades (Feature Requests)

- Explique primeiro o problema ou gargalo real.
- Em seguida, proponha a solução ou melhoria.

## Pull Requests (PRs)

- Dê preferência a PRs pequenos e modulares.
- Mantenha os commits focados e bem descritos.
- Preserve o estilo e as convenções do código.
- Explique as decisões de engenharia adotadas.

## Qualidade do Código

- Legibilidade e clareza
- Simplicidade (KISS / YAGNI)
- Performance quando justificável
- Segurança
- Documentação

## Contribuições Assistidas por Inteligência Artificial

Contribuições assistidas por IA são bem-vindas.

No entanto:
- Os contribuidores permanecem 100% responsáveis pelo código submetido;
- Todo código gerado por IA deve ser criteriosamente revisado;
- Os contribuidores devem entender detalhadamente o que estão submetendo;
- Código gerado por IA nunca deve ser mergeado sem validação humana.

Consulte o arquivo [FILOSOFIA_DE_DESENVOLVIMENTO.md](FILOSOFIA_DE_DESENVOLVIMENTO.md).
